# 6. Порядок работ на хостах

[Как меняется репозиторий](05-repo-refactor.md) · [оглавление](README.md) · консоль переноса каталога: [глава 7](07-move-clone.md)

Две ленты. Репозиторий можно готовить до ноды B. Прод трогаем по фазам ниже, каждую можно остановить. Вывод старого хаба идёт параллельно и перенос MinIO не блокирует.

## Уже сделано до старта

- Нода B существует, Ubuntu 24.04, адрес известен.
- Задержка A→B меньше 1,1 мс, ноды в одном городе. Локальный коллектор OTLP на A не закладываем.
- Сняты версии, тома, файрвол, SpoofDPI, боевой путь clone — [глава 2](02-as-is.md).
- Миграция метаданных opm-hub → OpenHub выполнена.
- В репозитории сервисы `opm_hub` и `opm_hub_db`, vhost и имя `hub-old.oscript.io` сняты. Редиректа нет. Том `postgres_data` остаётся. На ноде сертификат, DNS и остановленные контейнеры ещё на месте — это L1.
- Разовый ручной бэкап перед окном принят. Постоянная система бэкапов — отдельная задача после приёмки. До окна достаточно, чтобы копия лежала на B и dump базы открывался (`pg_restore --list`).

## Блокеры, без них M0 не начинать

Пользователь `deploy` заведён на A и входит в группу `docker`. Конфликт `docker-compose.yml` на A не блокирует: глава 7 сбрасывает каталог на `origin/master`. Блокер: на A сделана сверка `docker-compose config` из `origin/master` с реально запущенным стеком (образы, переменные, порты, тома) — перенос заодно применит файл из репозитория, расхождения надо знать заранее. Как коммиты репозитория стыкуются с этими фазами — [глава 5](05-repo-refactor.md).

## M0 — перенос каталога на A

Отдельное короткое окно, до сплита. Контейнеры с bind-mount пересоздадутся, тома `os_*` не копируются. Пошагово — [глава 7](07-move-clone.md). Репозиторий на этом шаге ещё со старым корневым `docker-compose.yml`.

Критерий: стек поднят из `/opt/oscript` с `origin/master`, каталог читается членами группы `docker`, `.env` в режиме `0640`, `COMPOSE_PROJECT_NAME=os`, сертификаты и логи смотрят в новый путь, сайты открываются, тома те же `os_*`.

## R1 — модули в git, на A ещё монолит

Коммит 1 из [главы 5](05-repo-refactor.md): `compose/`, примеры env и `ops/dc.sh` лежат рядом с неизменённым корневым `docker-compose.yml`. `config` колокации (`node_a.compose.yaml` + `overrides/colocated.yml`) совпадает с монолитом, тесты nginx и monitoring зелёные. На A этот коммит сам по себе ничего не переключает.

## R2 — Ansible в git

Коммит 2 из главы 5. `ansible-playbook --syntax-check` проходит. На A плейбук не запускают. На B роли `common`, `firewall` и `wireguard` впервые применяются в P0–P1, не в момент мержа.

## R3 — переключение входа на A

Коммит 3 из главы 5, отдельное окно после M0. На A: `git pull` и подъём через `ops/dc.sh`. Корневого `docker-compose.yml` уже нет: `COMPOSE_FILE` в `.env` указывает на колокацию (`node_a.compose.yaml` + `overrides/colocated.yml`), WireGuard для этого не нужен, R3 не зависит от P1. Тома те же, контейнеры пересоздаются из‑за меток Compose, но сохраняют имена `os_*_1` благодаря явным `container_name`.

## P0 — B как машина

Ручная часть — по [главе 4](04-ansible.md), раздел «Один раз руками на B» (`deploy`, ключ на A, клон в `/opt/oscript`, Ansible, `/opt/oscript-secrets/`). Дальше роль `common` и роль `firewall` (default deny) приводят B в порядок. Диск под тома проверяется отдельно. На A к этому моменту есть `deploy`, Python 3.9 и `sudo -n true`.

`iperf3` между нодами. Ориентир для спокойного rsync — от 200 Мбит/с. При меньшей скорости окно всё равно короткое: данных около 5 ГБ, — но цифру лучше знать заранее.

## P1 — туннель

Роль `wireguard` на обеих нодах. Ping. Compose прода не трогать. Подсеть не пересекается с docker bridge и маршрутами провайдера. Крупный ping с DF проходит.

Файрвол на A в этот же заход, с таймером отката и уже открытым 22/tcp.

## P2 — копия до окна

Порты `8080` и `5432` на адресе туннеля A открываются в окне P3, вместе с сервисами на B. До окна, пока писатели ещё работают, снимается копия:

- на B, в каталог вне Docker, rsync `os_minio_data` и `os_lgtm_data` — это и прогрев для P3;
- `pg_dump` базы OpenHub (и `opm_hub_db`, если старый хаб ещё не удалён) — файл на B, не на A;
- копия `.env`, `web/certbot/conf` и список томов — туда же.

На диске A свободно около 18 ГБ, второй полной копии там не размещать.

Критерий фазы: копия лежит на B, один пробный просмотр архива dump выполнен (файл открывается, `pg_restore --list` или аналог показывает ожидаемые таблицы). Полный restore в отдельный экземпляр — в приёмке, если окно позволяет; не вместо копии.

## P3 — окно

Подготовка, A работает:

1. На B создать тома командой `up --no-start`, чтобы у них были метки Compose. Контейнеры не стартовать. Имя проекта `os`, тома `os_minio_data` и `os_lgtm_data`.
2. Прогрев: `rsync -aHAX --numeric-ids` из `/var/lib/docker/volumes/os_minio_data/_data/` и тома lgtm в `_data` на B. Это не финальная копия.
3. В git уже лежат `node_a.compose.yaml` без minio и lgtm и оверлей `overrides/split.yml` с `extra_hosts` и публикациями на туннель. `config` обоих вариантов и тесты зелёные. На A до начала окна подключён оверлей `overrides/colocated.yml`.

История LGTM нужна, вместе с SQLite Grafana. Живой rsync её не фиксирует; финальный проход — после stop.

Окно:

1. Поставить на паузу проверки StatusCake (кабинет сервиса; на нодах агента нет). Включить на nginx статическую страницу 503 для `hub.oscript.io`, `s3.oscript.io` и `grafana.oscript.io`.
2. Остановить openhub на A (он пишет в MinIO). Jenkins, пока он пишет в облако, не останавливать.
3. `docker compose stop minio lgtm`. Не `down -v`.
4. Финальный `rsync --delete`. Сверить `du -sb`. После старта на B — число объектов MinIO (`mc`).
5. На B: `up -d` (minio, lgtm, hostmetrics). Bootstrap MinIO идемпотентен и не затирает ключи. Grafana с B отвечает на `10.9.0.2:3000` (проверка с B или через SSH-туннель).
6. На A заменить в `.env` оверлей (`COMPOSE_FILE=compose/node_a.compose.yaml:compose/overrides/split.yml`): активны `extra_hosts`, публикации `10.9.0.1:8080` и `10.9.0.1:5432`, у hostmetrics `OTLP_ENDPOINT=10.9.0.2:4317`, `up -d --remove-orphans`, reload nginx.
7. Убедиться, что новых томов с чужим префиксом нет.
8. Снять 503 и паузу StatusCake, когда P4 по основным URL зелёный. На время окна проверки могут коротко уйти в отказ — это ожидаемо.

Итоговая копия MinIO консистентна, потому что финальный rsync идёт по остановленному каталогу, включая `.minio.sys`.

## P4 — приёмка

- `https://s3.oscript.io` отдаёт существующий объект OpenHub; загрузка через хаб проходит.
- `https://grafana.oscript.io`: вход, дашборды OpenHub, datasource базы. Имена контейнеров в графиках живые (`os_openhub_1`).
- Трасса запроса хаба в Tempo (nginx → openhub).
- Метрики stub_status nginx в Prometheus.
- hostmetrics A и B в Grafana.
- Страница пакета и установка с `hub.oscript.io`.
- Обычная сборка Jenkins в облачный S3. Переключение Artifact Manager на `s3.oscript.io` в это окно не входит.
- Перезагрузка обеих нод: `wg0` поднимается сам, контейнеры с bind на адрес туннеля стартуют без рук.
- `nmap` с постороннего хоста: на B виден только 22; 51820/udp открыт лишь для адреса A и снаружи выглядит закрытым; 9000, 3000, 4317, 4318 на публичном адресе B закрыты. На A нет новых публичных портов.
- `certbot renew --dry-run` на A.
- Задержка страницы пакета и установки не разъехалась с замером до окна.

## P5 — бэкапы после

`local_backup.sh` покрывает только `web_content` и на две ноды не рассчитан. Минимум, который стоит записать следом, уже не как блокер окна: dump томов B и `pg_dump` OpenHub хранятся не на той ноде, где источник. Автоматизация — отдельная задача.

## P6 — откат

Пока на B не появилось записей, которых нет на A:

1. Остановить minio и lgtm на B.
2. Вернуть оверлей `overrides/colocated.yml` на A (`COMPOSE_FILE=compose/node_a.compose.yaml:compose/overrides/colocated.yml`); локальный `OTLP_ENDPOINT=127.0.0.1:4317` задаётся самим оверлеем.
3. Запустить minio и lgtm на A со старыми томами. Тома A до этого не удалять и не перезаписывать.

Если на B уже писали, откат — обратный rsync в новое окно. Это говорят до P3, не после.

## L1 — старый хаб

В репозитории сервисы, vhost и имя уже сняты. Том `postgres_data` остаётся в compose и на ноде. Редиректа нет. Пока на ноду не выложен этот compose, остановленные контейнеры ещё могут лежать рядом.

1. Просмотреть логи nginx по `hub-old` за последние недели и понять, кто ещё ходит. Редиректа не будет в любом случае; лог нужен, чтобы предупредить живых клиентов `opm` со старым URL.
2. `pg_dump` отложить в сторону (если контейнер уже остановлен — снять dump с тома, подняв Postgres разово, либо признать дамп из P2 достаточным).
3. Выложить этот compose и пересобрать nginx: vhost в образ уже не входит. Потом `certbot delete --cert-name hub-old.oscript.io` и запись в `web/certbot/conf/renewal/`. Обратный порядок оставляет nginx без файлов сертификата, если старый образ ещё содержит server-блок.
4. `up -d --remove-orphans` снимает контейнеры сервисов, которых в файле больше нет. Том `os_postgres_data` не удалять.
5. Снять DNS-запись `hub-old.oscript.io`.
6. Статику старого хаба в `web_content` (`/var/www/hub.oscript.io`) не путать с сайтом. Чистить, когда архив больше не нужен.

## P7 — Portainer

После P4. Образы с закреплённым тегом, не `latest`.

- На B: `portainer/portainer-ce`, сокет Docker, публикация `10.9.0.2:9443:9443`.
- На A: `portainer/agent`, публикация `10.9.0.1:9001:9001`, `AGENT_SECRET` из vault.
- Браузер: SSH-туннель на `10.9.0.2:9443`. Отдельного публичного имени нет.

## Позже, не в этих работах

Вынос `openhub` и `openhub_db` на B: правка карты размещения, публикация `10.9.0.2:3333`, статический `proxy_pass`, в `OSHUB_INSTANCE_TRUSTED__PROXIES` добавляется подсеть туннеля, Grafana видит базу локально, публикация 5432 на A снимается. Тома `os_openhub_data` и `os_openhub_postgres_data` едут по той же схеме, что P3. Тогда A остаётся прокси, и бэкап базы становится важным так же, как бэкап MinIO.

CoreDNS, третья нода, registry, публичный Portainer — только если появится отдельное решение. В модули заранее не закладываются.

## Риски

| Что может случиться | Что сделано в плане |
| --- | --- |
| `up` из нового каталога без имени проекта | пустые тома `oscript_*`; до первого up в `.env` стоит `COMPOSE_PROJECT_NAME=os` |
| nginx не видит MinIO на B | статический `proxy_pass` и `extra_hosts`, без подмены Docker DNS |
| OpenHub не достучится до OTLP | на B опубликован `10.9.0.2:4318` |
| На B нет метрик хоста | hostmetrics в сборке B |
| Клиенты ещё ходят на hub-old | смотрим лог до снятия сертификата и DNS; редирект не обещаем |
| Bind-mount мимо `/opt/oscript` | проверка `config` на абсолютные пути |
| `.env` не подхватился | `--project-directory` и `env_files` |
| B или туннель упали | хаб без файлов и s3 недоступны; это принято. Откат P6, пока тома A целы |
| Docker раньше WireGuard | drop-in `After=wg-quick@wg0`, проверка перезагрузкой |
| ufw не закрывает порты контейнеров | bind на адрес туннеля и `DOCKER-USER`, проверка `nmap` |
| Секрет попал в публичный git | vault и inventory вне репо, gitignore, просмотр диффа |
| Единственная копия vault на B | копия файла и пароля у оператора |
| A на Ubuntu 16.04 без обновлений безопасности | принято; Docker не переустанавливаем, Ansible ходит через отдельный Python 3.9 |
| SpoofDPI слушает все интерфейсы | роль переводит bind на docker0 и это проверяется `ss` |
| Файрвол закрыл SSH | 22/tcp до включения, таймер отката |
| Пустая группа edge в inventory | шаблон пира WireGuard без хаба не рендерится |
| `.env` на двух нодах разъехался | один vault, два шаблона |
| Диск A кончился во время копии | копии только на B |

## Готовность репозитория к окну

- [ ] Колокация `node_a` + `overrides/colocated.yml` по `config` совпадает с боевым монолитом; `config` с `overrides/split.yml` валиден
- [ ] `node_b` содержит minio, lgtm, hostmetrics и валиден
- [ ] Нет `depends_on` на сервис другой ноды
- [ ] Образы и env openhub, nginx, hostmetrics, lgtm совпадают с боевыми, openhub остаётся 0.21.0
- [ ] `container_name: os_<сервис>_1` явно задан во всех модулях `compose/apps/*.yml`
- [ ] `name: os`, bind-источники под `/opt/oscript`
- [ ] Ansible: корневой `ansible.cfg`, control node B, на обеих нодах пользователь `deploy`, на A ещё Python 3.9, пакеты через `apt-get`, WireGuard с handler, app через git (`version: "{{ deploy_ref }}"`) и `project_name`
- [ ] Роли `firewall` и `spoofdpi` описаны кодом по эталону главы 2
- [ ] В репо нет секретов и боевого inventory; есть примеры без значений
- [ ] Тесты nginx и monitoring зелёные
- [ ] `AGENTS.md` и корневой README описывают две ноды и `ops/dc.sh`
- [ ] Drop-in Docker `After=wg-quick@wg0` есть в роли

## Готовность прода

- [ ] Пункты P4
- [ ] На A нет контейнеров minio и lgtm
- [ ] Служебные порты B не слушаются на публичном адресе
- [ ] Копия P2 сделана до окна, dump открывается
