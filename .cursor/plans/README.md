## Статус

Решения приняты. На ноде A каталог стека уже `/opt/oscript`: владелец `deploy`, группа `docker`, в `.env` стоит `COMPOSE_PROJECT_NAME=os`, тома `os_*`, стек поднят корневым `docker-compose.yml` с `origin/master`.

В ветке `feature/multi-host` готовы этапы 1–2 git: модульный `compose/` и каркас `ansible/` (роли, `ansible.cfg`, образцы без секретов). Плейбук на хостах не запускали. Проверка: `./ansible/test/run.sh`.

## Перед первой правкой на хостах

Рефакторинг идёт в ветке `feature/multi-host`, `master` не трогается до остановки старого стека. Источник деплоя — параметр `deploy_ref` (сейчас `master`, на время миграции `feature/multi-host`).

Один раз руками остаётся пользователь `deploy` на ноде B (глава 4). На A учётка `deploy` уже есть. Интерпретатор модулей Ansible на A уже стоит: `/opt/python3/bin/python3` (CPython 3.12); в `PATH` его нет, вызов только полным путём. Коммиты в git и окна на хостах стыкуются по главе 5.

Публичный IP ноды A в книгу не входит: его вписывают в inventory на ноде B.
