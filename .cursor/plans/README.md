## Перед первой правкой на хостах

Рефакторинг идёт в ветке `feature/multi-host`, `master` не трогается до остановки старого стека. Источник деплоя — параметр `deploy_ref` (сейчас `master`, на время миграции `feature/multi-host`). Локальный конфликт `docker-compose.yml` на A в работу не берётся: при переносе каталога дерево сбрасывается на `origin/master`.

Один раз руками: пользователь `deploy` на обеих нодах и Python 3.9 на A (глава 4). Каталог стека уезжает из `/home/andrei/os` в `/opt/oscript` с теми же томами `os_*` (глава 7). Коммиты в git и окна на хостах стыкуются по главе 5.

Публичный IP ноды A в книгу не входит: его вписывают в inventory на ноде B.
