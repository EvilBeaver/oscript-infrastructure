# 1. Решения

[Оглавление](README.md) · дальше: [как устроена нода A](02-as-is.md)

## Зачем

Один репозиторий описывает две независимые сборки Docker Compose и применяет их через Ansible. Диск и нагрузка MinIO и Grafana/LGTM уезжают на вторую машину в том же городе, у другого провайдера. Kubernetes и Docker Swarm не вводятся.

Публичные домены продолжают открываться как сейчас. `s3.oscript.io` и `grafana.oscript.io` по-прежнему указывают на ноду A. Служебный трафик между нодами идёт по WireGuard. Состав сервисов задаёт git.

Падение ноды B или туннеля делает недоступными скачивание пакетов с хаба и `s3.oscript.io`: файлы OpenHub лежат в MinIO. Это принятый риск. Сайт, Jenkins и TLS при падении B продолжают работать.

## Ноды

| | Нода A, edge | Нода B, worker |
| --- | --- | --- |
| Где | действующий хост `oscript.io` | `<IP B>` (в книгу не входит), Aeza, Москва, пустая Ubuntu 24.04 |
| Задержка до другой ноды | меньше 1,1 мс по замерам до туннеля; после WireGuard перемерить | |
| Сервисы | nginx, site, jenkins, certbot, tg_bot, s3-sync, openhub, openhub_db, hostmetrics | minio, lgtm, hostmetrics |
| Позже, не в окне переноса | Portainer Agent | Portainer Server |
| Каталог | `/opt/oscript` после [переноса](07-move-clone.md). Сейчас боевой clone — `/home/andrei/os`. Новый путь общий для людей из группы `docker`, не домашний каталог | `/opt/oscript`, новый clone, те же права |
| Имя проекта Compose | `os`. Тома остаются `os_*`, хотя каталог больше не называется `os` | то же `os` |
| Кто применяет Ansible | пользователь `deploy` | пользователь `deploy` |

Jenkins остаётся на A: ему нужен `/var/run/docker.sock`. Общий том `web_content` живёт только на A. `s3-sync` по-прежнему зеркалит его во внешний S3 (Yandex), не в MinIO.

На A сосредоточены публичный вход, базы и приложения. Падение A изолирует B от интернета. Для этого разреза так и задумано: B не публикует сервисы наружу.

## Транспорт и имена

- WireGuard, подсеть `10.9.0.0/24`. A — хаб `10.9.0.1`, слушает UDP 51820. B — пир `10.9.0.2`.
- Служебные порты публикуются на адрес туннеля, не на `0.0.0.0`. С интернета на B открыты только SSH и UDP 51820 с адреса A.
- Общий DNS для двух адресов не поднимаем. Кросс-нодовые имена — `extra_hosts` из inventory. Локальные имена на A (`site`, `jenkins`, `openhub`, …) резолвит Docker DNS. Контейнерам не задавать `dns:`.
- Публичный DNS не меняется: все `*.oscript.io` смотрят на A.

Локальный OTLP-коллектор на A не нужен: задержка между нодами маленькая. После туннеля ещё раз снять `ping` и `iperf3`.

## Как деплоим

- Control node — нода B. Оператор заходит на B и запускает `ansible-playbook`. GitHub Actions в первой версии нет. Позже допустим self-hosted runner на B; runner в облаке GitHub control node не становится.
- Ansible управляет обеими нодами от пользователя `deploy` (sudo без пароля, группа `docker`). На A система остаётся Ubuntu 16.04.7, Docker не переустанавливается. Один раз руками: Python 3.9 и учётка `deploy`. Дальше — роли.
- Ветка деплоя задаётся параметром `deploy_ref` (ветка, тег или SHA) репозитория `EvilBeaver/oscript-infrastructure`. Пока старый стек работает, это `master`. Весь рефакторинг (главы 3–5) ведётся в отдельной ветке `feature/multi-host`, `master` не трогается до остановки старого стека. Новый стек разворачивается с `deploy_ref=feature/multi-host`; в `master` ветка вливается после приёмки, и `deploy_ref` возвращается к `master`. Fork и незакоммиченный конфликт compose на A к деплою не подмешиваются.
- Секреты: файл `ansible-vault` лежит на B вне репозитория, на хостах Ansible рисует `.env`. HashiCorp Vault не ставим. Репозиторий публичный — в git нет ни открытых секретов, ни ciphertext.
- Образы собираются на той ноде, где крутится сервис, из текущих каталогов (`web/nginx`, `jenkins`, `minio`, `S3`). Отдельный registry и перекладка дерева в `build/` / `assets/` не нужны.
- Portainer желателен и не блокирует перенос. Server на B, Agent на A, интерфейс только через SSH на адрес туннеля.

## Что выводим и что откладываем

Старый хаб снят из репозитория: сервисы `opm_hub` и `opm_hub_db`, vhost и имя `hub-old.oscript.io`. Редиректа нет. Том `postgres_data` (`os_postgres_data` на ноде) остаётся. На ноде A ещё остаются остановленные контейнеры, сертификат и DNS — их снимают по [разделу «Старый хаб»](06-work-order.md). Этот заход не блокирует перенос MinIO. В модули нового стека сервис не переносится.

Отложено и в эту книгу как работы не входит: CoreDNS, публичное имя Portainer, внешний registry, вынос Jenkins, третья нода, перенос OpenHub на B. Последнее заранее учтено тем, что размещение сервиса — данные inventory, а не правки каждого модуля. Аварийная замена ноды A целиком (новая машина и смена DNS) возможна, в план работ не входит: клиенты долго держат старый DNS.

## Окно

Простой `s3.oscript.io`, Grafana и `hub.oscript.io` (на время окна nginx отдаёт для него статический 503) — до часа, по факту ожидаются минуты: на B уезжает около 5 ГБ. Сайт и Jenkins в это окно не обязаны останавливаться.
